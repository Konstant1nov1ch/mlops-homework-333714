## Цель

Подготовить сервис поиска по инженерным инструкциям к безопасному выпуску в Kubernetes с проверкой качества и возможностью отката.

## Выполнение

Runbook Search API использует гибридный TF-IDF индекс по корпусу из 12 документов. Индекс собирается при создании Docker-образа. Сервис предоставляет поиск `/v1/search`, рекомендации, `/livez`, `/readyz`, `/meta` и `/metrics`.

Helm chart принимает образ по digest. Pipeline выполняет проверку качества, сборку и публикацию образа, развёртывание в staging и после подтверждения — в production. Для проверки отката предусмотрен режим `reverse`.

## Результаты проверки

| Режим | MRR | Recall@3 | Результат |
|---|---:|---:|---|
| `normal` | 0,9375 | 1,0 | Проверка пройдена |
| `reverse` | 0 | 0 | Проверка качества отклонена |
| После отката | 0,9375 | 1,0 | Качество восстановлено |

В режиме `reverse` `/readyz` продолжал отвечать, но semantic smoke обнаружил ухудшение поиска. Helm вернул рабочую ревизию, после чего проверка прошла. В staging и production подтверждены одинаковые образ, ревизия исходников и индекс; при проверке оба Deployment были готовы `1/1`.
