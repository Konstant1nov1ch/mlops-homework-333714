# Лабораторная работа 3. Поиск по базе знаний и MCP

**Студент:** Пинчук Константин Константинович  
**ИСУ:** 333714

## Цель

Создать портал поиска по базе знаний с MCP-сервером, ответами с указанием источников и маршрутизацией между облачной и локальной моделями.

## Выполнение

Корпус содержит 36 редакций, 35 уникальных ID, 6 разделов и 12 подразделов. Для поиска построен индекс SQLite FTS5 с фильтрами статуса, пути и версии. MCP-сервер предоставляет инструменты `search_docs`, `get_doc` и `list_sections`. Портал показывает результаты поиска, дерево документов и ссылки на конкретные редакции и разделы.

Основной маршрут использует llm7, резервный — локальную модель DeepSeek-R1-Distill-Qwen-1.5B. Для модели, MCP и портала подготовлены Deployment и Service в Kubernetes. Веса модели размещены в PVC; их SHA-256: `f3bdf9cf31dee4b57ae4e455a1cb0d01b5c2c1b50d72d3112141c195506c2840`.

## Результаты проверки

- Поиск нашёл все ожидаемые документы в первых пяти карточках для восьми контрольных вопросов. Независимый MCP-клиент проверил инструменты и редакции M-05@1.1 и M-05@2.0.
- Модель выполнила генерацию внутри кластера; после пересоздания Pod веса сохранились и генерация повторилась.
- При проверке llm7 через локальный портал восемь контрольных вопросов получили облачные ответы. Через портал в Kubernetes и шлюз шесть из восьми запросов завершились по маршруту `cloud`, два — в режиме `search_only`.
- При синтетическом ответе `429` запрос с тем же контекстом передавался локальной модели; после восстановления имитатора следующий запрос вернулся на облачный маршрут. Содержательный локальный ответ в этом сценарии получить не удалось — портал вернул `search_only`.

Прямое соединение Pod с llm7 при проверке завершалось таймаутом. Для облачных запросов из кластера использован шлюз через компьютер с доступом к llm7. Подробные ответы сохранены в [результатах локальной проверки](ЛР3-проверка.json) и [проверки в кластере](ЛР3-проверка-кластер.json).
